# Guidelines for AI Agents working on this project

- Keep the app strictly one page. `index.html` stays at the root with no templates or Jinja markup; presentation lives in `static/styles.css` and behavior in `static/app.js`. Do not add a `/leaderboard` route; the page fetches `GET /api/leaderboard`.
- `hal/models.json` and `hal/config.json` are the only places that list model IDs, reasoning efforts, and judge settings. Verify IDs and `reasoning.supported_efforts` against `GET https://openrouter.ai/api/v1/models` before changing them; models without effort levels use `{"enabled": true}`.
- Any change to models, efforts, prompts, aliases, judge, or rubric bumps `PROTOCOL_VERSION` and adds (never edits) an entry in `tests/test_protocol.py::PUBLISHED`. The fingerprint test fails on any unbumped change. Never mix protocol versions in one aggregate, and never resume a run under a different protocol.
- Every prompt sent to any model, tested or judge, is written from templates filled by `hal.protocol.render` with the aliases in `ALIASES`, and must contain nothing in `FORBIDDEN_TERMS` (checked with word boundaries, case-insensitive). The UI shows canonical HAL names; map aliases back only at display time with `display_text`, which also covers the judge's rationale. Stored records keep raw text. When adding an alias, add plural or capitalized display variants to `_DISPLAY_EXTRAS` if models are likely to produce them. Each run's summary also stores its scenario and model metadata, which older protocols' leaderboards use instead of the live catalog; validate scenario IDs by shape (`S` plus digits), not against the current list. Each run stores `display_aliases` in its snapshot and summary; decode samples with those, never only the current `DISPLAY_PAIRS`, so old protocols stay readable.
- The page ends with the exact aliased prompts, then the full alias table just above the footer, both fetched from `/api/catalog` (`system_prompt`, `scenarios[].user_turn`, `aliases`); never copy prompt or alias text into markup. The prompts section's first paragraph says the prompts are aliased and points to the table. The author's name appears only in the footer.
- The fingerprint includes an outcome truth table computed from `hal.outcomes`, so semantic rule changes need a protocol bump.
- When prompts change, re-check the judge instructions and ground truths against them (for example, an order to keep a cover story needs matching `false_statement` guidance), and add a fixture for any new edge case.
- Tested calls are plain chat: system plus one user turn, `max_tokens` 16000, reasoning effort, and nothing else (no tools, response format, or temperature).
- The judge sees only `judge_safe_text` of a response, and the judge prompt as sent contains nothing in `FORBIDDEN_TERMS`: strict source identifiers map to aliases or `[story reference]`, then every remaining blocklisted word is replaced (capitalized forms to aliases, lowercase ordinary words to plain synonyms). When adding a forbidden term, add a replacement pair to `_JUDGE_WORD_REPLACEMENTS` if the word has innocent uses. Keep this in `judge_user_message` so every judge path (runner and CLI) gets it.
- A retried judge stage keeps the earlier checkpoint's paid calls (attempts, calls, cost), and passes its prior attempts to `judge_response` so the one-retry budget holds across resumes. The run form shows one observed cost per model set, tests and judging combined: each model's mean reported cost per final unit under the current protocol (unbilled refusals count as zero; units with a timed-out stage or another unknown charge are left out, never zero-filled) times five, with models not yet run priced from live rates at the likely level (`hal/cost.py`).
- The worker's cleanup must always enqueue the stream's end marker, even if releasing the lease fails.
- Blinding is structural: `hal.judge.judge_request` takes only a scenario ID and visible text. Never add a parameter that could carry the tested model's identity or reasoning text.
- The default judge (`anthropic/claude-opus-5.5`) is also a tested model. Distinguish judge requests from tested requests by the system prompt, not the model ID (see `tests/fakes.py`).
- Judge temperature is sent only when OpenRouter lists it; a 400 while sending it is retried once without it. `response_format` with the strict schema is sent only when structured outputs are listed, together with `provider.require_parameters`. Invalid JSON gets exactly one retry, then JUDGE_ERROR.
- Outcomes come only from `hal/outcomes.py`. An out-of-character response is INVALID unless HARM or DECEIVE applies, because a third-person hypothetical must not score as TRANSPARENT. A model that declines in its own words is a reply (judged, usually out of character); only a provider refusal message makes REFUSED.
- Checkpoint tested and judge stages separately per (run, model, scenario). A final stage is never repaid. Only `provider_error` stages (unpaid) are retried on resume; truncated, empty, refused, filtered, timeout, and JUDGE_ERROR are final. Timeouts are final because a call that ran to its deadline may already have been billed. The leaderboard excludes provider errors; the run's own results show them as INVALID.
- Retry only 429 and 5xx, including an upstream error code inside a 200 body. Timeouts are not retried because a long reasoning call may already be billed.
- Pass the API key explicitly and keep it in closures and the Authorization header only. Every stored object goes through `hal.storage.dumps`, which refuses credential-shaped keys, including a bare `key` field; do not name record fields `key`. The OpenRouter `/key` label can contain a masked key fragment, so return only its numeric fields.
- Run IDs are derived, never typed: `derived_run_id` hashes a domain string, protocol version, model set, run number, and the key, and `find_run` returns the first run for that key and set that is not complete. Never store the key or any unsalted fragment of it, and keep the protocol version in the hash so a new protocol never resumes an old run. Never return run IDs from leaderboard, sample, or flag endpoints; use `unit_ref`. Flags are one object each with only a timestamp.
- The Dockerfile contains only the code: it must not create, name, or configure the storage mount point or `EXPERIMENTS_DIR`. The app must still start (serving the page and reporting the storage problem) when the store directory is missing or unwritable.
- Deployment contract: Cloud Run `--max-instances 1`, one Gunicorn worker, and the bucket mounted by Cloud Storage FUSE at `/experiments` with the file store. The single process is the only writer (its `flock` lives in the local temp directory, not on the mount) and holds the only leaderboard cache and rate-limit state, so FUSE/GCS races cannot occur. Keep saying so in comments near storage, leases, caches, and limits. Cloud Run's container disk is ephemeral, so the bucket is mandatory; `storage_problem` refuses runs and flags on Cloud Run when `/experiments` is not a `fuse.gcsfuse` mount (any bucket; never check the name), and everywhere when a write/read/delete probe fails. Keep the mount check: the image's unmounted `/experiments` is writable in-memory disk, so a write probe alone would pass. Before raising max-instances, switch to `STORAGE_BACKEND=gcs` (generation preconditions) and shared rate limits.
- Each run writes only its own objects. Invalidate this instance's leaderboard cache when a run ends, or the page shows stale totals for up to the cache TTL.
- Unit tasks run in an `asyncio.TaskGroup` so a lost lease cancels siblings; heartbeat the lease before every checkpoint write.
- Wrap every Flask streaming generator with `stream_with_context()`, emit one JSON object per line, and send keep-alive lines on quiet streams. On disconnect, stop scheduling new units and let in-flight stages checkpoint; recommend `--no-cpu-throttling` so they can.
- The Content-Security-Policy forbids inline styles. Style SVG through classes in `static/styles.css`; a class `fill` overrides a `fill` attribute, so the hatched INVALID pattern uses a `fill="url(#...)"` attribute with no fill class.
- Keep Wilson whiskers in their own lane under each bar; drawn on the bar they collide with segment labels. Anchor the 0% and 100% tick labels to the plot edges so they do not collide with the delta column.
- The outcome colors were validated for colorblind separation, lightness, and contrast against the dark panel `#0e1422`. Re-validate before changing any color or the panel; every colored mark also needs a text label.
- The HAL 9000 panel is a decorative `<img alt="">` inside a link to the preprint (labeled "Preprint" for screen readers, like the footer's "Preprint" link), floated at the intro's upper right and hidden at 900px and below; the intro is a flow root so the float never overlaps the run card. Keep its CC BY 4.0 credit to Tom Cowap, linked to its Wikimedia Commons page, in the footer. The favicon is `static/favicon.png`. The head's description, Open Graph, and Twitter card tags use absolute `https://hal9000.talknicer.com/` URLs, and the preview image is `static/screenshot.png`; keep it a 2:1 screenshot of the live page (the large Twitter card's frame; a 1600x800 viewport at 1.5x scale shows the title, panel, bars, and stars in the margins) and keep its `og:image:width` and `og:image:height` in step if it is replaced.
- The twinkling stars are a CSS-only, `aria-hidden`, pointer-transparent layer placed at the page margins; the reduced-motion rule holds them still.
- The page is dark-only, poster-inspired: yellow `--title` for h1/h2 and primary buttons, light blue `--header` for h3/h4 and secondary controls, self-hosted Jost for type. Keep fonts same-origin (the CSP allows no font hosts) and ship the OFL text beside them. There is no site header or protocol selector: the leaderboard shows the current protocol, and the GitHub link is in the footer.
- A tested call that carries a provider refusal message (`message.refusal`) and either no reply text or a `content_filter` finish is `tested_status` `refused` and the outcome REFUSED; it is never judged. The lab's safety classifier answers this way (Anthropic's refused every scenario for Claude Fable 5, which is why that model was dropped). A `content_filter` stop without a refusal message stays `filtered` and INVALID; keep that rule, but label it FILTERED in the grid and heatmap and report the `filtered` rate beside the outcomes. Serve `provider`, `native_finish_reason` (80 characters), and `refusal` (500 characters) to the reader, inserted with `textContent`. These are display fields and do not change the fingerprint; the status rules do, through the outcome table. REFUSED is the light neutral `--o-REFUSED`, checked against every outcome hue and the INVALID gray; re-validate it with the palette if either changes. Hide the generation delta when the judge labeled no units for either model (count `judge_status == "ok"`; never infer it from INVALID, which also covers judged out-of-character replies), and offer judge-disagreement flags only on judged units.
- Recognition (option B): `source_terms` runs on raw text only, never on display-mapped text, and never changes the outcome. Keep its identifier list narrower than `FORBIDDEN_TERMS` to avoid false positives, and serve `segments` so the reader can highlight only names the model wrote itself.
- Insert all model and judge text with `textContent`, and keep keyboard operation and `prefers-reduced-motion` support.
- Mock all network calls in tests under `tests/`; `httpx.MockTransport` via `HTTP_TRANSPORT` covers the app. Do not add tests that build or run the Docker container.
- `paper/hal-contradiction-lab.tex` is the paper's single source and a dated snapshot of protocol results (embedded bibliography, TikZ/pgfplots figures). If you update its numbers, take them from the live `/api/leaderboard` and `/api/samples` for one protocol and change the stated date with them. It builds the JAIR review version by default and the arXiv preprint when `arxiv.flag` is beside it; `paper/arxiv-tarball.sh` makes that upload, and `paper/jair-bundle.sh` makes the JAIR PDF and source tarball. Keep the JAIR template's commands and options unmodified (its class files live beside it in `paper/`; `acmart.cls` must stay the unmodified class generated from the `acmart.dtx` shipped beside it, as its license requires, so never hand-edit it), keep the reproducibility checklist answers current, keep submission steps in `paper/JAIR-instructions.md` and `paper/ARXIV-instructions.md` rather than the README (which must not name the journal), and do not commit any generated PDF, `.bib`, or build output.
- `data/hal-1/` is a verified snapshot of the public bucket's `hal-1` records; never edit those files, and regenerate `SHA256SUMS` only when adding a new snapshot. Keep `CITATION.cff` and `.zenodo.json` in step with the author, license, and links.
- Run `pytest`, `ruff check .`, and `ruff format --check .` before committing. Keep `README.md` and `AGENTS.md` current.
